# Features

Every conversation or feature request for this project, oldest first, each with its own file.

Newer requests override older ones where they conflict.

| # | Request | Summary |
|---|---|---|
| 1 | [Foundation: naming, app stack, architecture](2026-11-08-foundation.md) | The first design conversation named the app Launchpad and chose a local-only Python app in its own window with a React front end. It also set the architecture around a separate agent library with swappable engines, Claude first. |
| 2 | [Orbit UI direction and prototype](2026-11-08-orbit-ui-direction.md) | The "Orbit" look was picked, with planner chat on the left and crew status plus a request queue on the right. A one-file HTML prototype of that window was made to refine it. |
| 3 | [Planner, plan files, runs and cost (first design)](2026-11-08-planner-and-plan-files.md) | This is the first design for how the planner interviews the user and what plan files the orchestrator reads. It also covered where run records live and how failures and costs are handled, much of it later replaced by the V1 loop. |
| 4 | [Agent library: agentlib](2026-11-08-agentlib.md) | A shared Python library, agentlib, was built so every agent is defined and run the same way on Claude, Cursor or a free fake engine. It handles sessions, Python tools, questions to the user and tool permissions. |
| 5 | [First working app](2026-11-08-first-working-app.md) | The first running version opened the Orbit page in its own window and let you chat with a planner. The planner's questions appeared as answerable cards. |
| 6 | [V1 loop: planner, approval, orchestrator, builders](2026-11-12-v1-loop.md) | The core loop was built: the planner drafts a plan, you approve it, and an orchestrator runs one builder per step and writes a report. It also added question and permission cards, a per-session folder, live costs and a zero-token demo. |
| 7 | [Builder write / shell guard: known limits](2026-11-13-builder-guard-limits.md) | This records what the builder's file-write check and shell command blocklist cannot catch. It lists ways to close those gaps later. |
| 8 | [Activity feed](2026-11-13-activity-feed.md) | Every tool call by every agent now shows up live as a one-line activity entry. The entries are replayed on reconnect and saved to a log in the session folder. |
| 9 | [Live smoke run](2026-11-13-live-smoke-run.md) | The whole loop was run once against the real Claude engine on a scratch project and passed for about eight cents. Two small fixes came out of it. |
| 10 | [UI review fix round](2026-11-13-ui-review-fixes.md) | A review of the running window led to a round of fixes to cards, meters, reconnecting and cost totals. Every place now shows the same session total. |
| 11 | [Regular session: Pilot (plain Claude Code chat)](2026-11-13-pilot-regular-session.md) | A plain Claude Code chat was added that works in the chosen folder exactly as Claude Code does, with no plan and no Launchpad guards. Its permission prompts and questions show up as cards in the app. |
| 12 | [Visual sidecar for the planner](2026-11-13-visual-sidecar.md) | The planner can show a few quick visual options, such as charts, palettes or layouts, beside the chat so design questions are settled by picking one. A cheap separate agent draws them in sealed frames that cannot reach the internet. |
| 13 | [Send-back and approve again](2026-11-13-send-back-approve-again.md) | A plan can be sent back, revised and approved again, even after a run has finished. Reloading the page no longer loses a draft that is waiting for approval. |
| 14 | [Cost audit, thinking / effort facts and planner cost study](2026-11-13-cost-audit.md) | This checks where every cost figure comes from, what each agent costs at minimum, and how thinking effort is set. It also measures where a planner conversation spends its money and lists ways to save. |
| 15 | [Builder permissions: timed cards and autopilot](2026-11-13-builder-permissions-autopilot.md) | Builder permission cards now expire after a set time and count as denied, and writes outside the project ask instead of being refused. An optional autopilot approves every builder request without asking. |
| 16 | [Agent system prompts: planner without the Claude Code preset, builder on it](2026-11-13-agent-system-prompts.md) | The planner and most agents keep their own short instructions instead of Claude Code's built-in ones. The builder was switched to Claude Code's own instructions for a small extra cost per step. |
| 17 | [Planner: edit-based revisions](2026-11-13-planner-edit-revisions.md) | The planner now changes a draft plan with small edits instead of rewriting it each time. This roughly halved the cost of revising a plan. |
| 18 | [Planner: start on Sonnet, promote to Opus](2026-11-13-planner-promotion.md) | Each planning session starts on the cheaper Sonnet model and can switch once to Opus when the request looks hard or when you ask. The switch keeps the conversation going without a restart. |
| 19 | [Connected folders, settings store, File Explorer and hand-editing](2026-11-13-connected-folders.md) | Sessions can now run in any of several connected project folders, and settings are kept per user instead of as launch options. A File Explorer lets you browse those folders and safely edit markdown files, with backups. |
| 20 | [React port of the front end, then a visual polish pass](2026-11-13-react-port.md) | The window now runs a React front end instead of one hand-written HTML file, with the same screens and behaviour. It also got a tidier look on the same Orbit theme, and the old page is still at /classic. |
| 21 | [Plain agent names, agent registry and user-added agents, Crew cards, Planner / Claude Code switch, wider Visualizer](2026-11-13-agents-crew-visualizer.md) | Agents got plain names, and you can add your own agents from the Crew tab for the planner to assign to plan steps. The Free Flight tab became a Planner / Claude Code switch, and the Visualizer can draw with more charting libraries. |
| 22 | [Code organisation and documentation](2026-11-14-code-organisation.md) | This tidy-up moved every built-in agent into its own folder and split a large module, with no change in behaviour. It also added an architecture overview and a README in each main folder. |
| 23 | [Request records: one file per request](2026-11-14-request-records.md) | Each conversation or feature request is now saved as its own file, listed here with a two-sentence summary. The old combined decisions file was split into these files and removed. |
| 24 | [Skills, primary and additional folders, CLI naming, model picker, Git repos panel](2026-11-16-skills-folders-picker-git.md) | Agents now use skills found in the working folders, scoped per agent from the Crew tab and nameable by the planner per plan step, and a session works in one primary folder plus any ticked additional ones. The Claude Code chat is now called "CLI", the planner's model and harness are chosen from a picker under the chat box, and the Files tab shows a Git repos panel with status, changed files, commit and push. |
| 25 | [CLI-then-model picker, CLI choice for the CLI chat, "Other" agents, smaller activity feed, question files](2026-11-17-cli-picker-other-questions.md) | The model picker now asks for a CLI first and then shows that CLI's models, the CLI chat has the same picker, agents have an "Other" purpose, and the Missions activity feed takes less room. Every answered question is saved as its own markdown file in the session folder, and an Auto answers switch takes each question's recommended answer so work carries on while you are away. |
| 26 | [Undefined roles: tally, independent review, define as an agent; Auto answers for builders only; one place for cost totals](2026-11-17-role-review.md) | The planner now names a role on plan steps that have no defined agent, Launchpad records each role's uses, and from the Crew tab an independent reviewer writes a case on five tests for whether the role earns its own agent definition, with the decision left to you. Auto answers now applies to builders only and answers every question with the builder's own recommendation, and cost totals are added up in one place on the server. |
| 27 | [Settings page, CLI connections and MCP library](2026-11-17-settings-connections-mcp.md) | Settings is now its own page whose first section lists Claude Code and Cursor, each with a Test button that checks the tool is installed and that Launchpad can reach it. An MCP library in Settings stores, tests and imports the user's MCP servers, and every agent's page in Crew has a picker for the servers that are connected, with none given to any agent by default. |
| 28 | [Analytic spaces (draft, parked)](2026-11-17-analytic-spaces-draft.md) | An early scoping conversation settled that a space would be a light routing page linking to methodology pages that already exist in a wiki, not a second copy of them. It was parked before anything was approved, with where a space lives, what picking one does and how sub-studies are tracked left open. |
| 29 | [Sidebar navigation](2026-11-17-sidebar-navigation.md) | The tab list at the top of the window is now a sidebar on the left that can be collapsed to icons, with Settings at the bottom, because more views are coming. It is built on its own branch on top of request 27 and has been checked by tests but not yet looked at in a running window. |
| 30 | [Workflows](2026-11-17-workflows.md) | A Workflows view is approved where each registered workflow is a JSON file describing a straight line of stages, each either an agent with markdown files attached or a human review stop with a checklist and sign-off. Runs save their records to a folder the user chooses, a test run reuses one folder that is cleared each time, and it is built after the sidebar. |
| 31 | [MCP sign-in: OAuth, .env references and token from a command (draft, parked)](2026-11-17-mcp-sign-in-draft.md) | A scoping conversation proposed four ways for an MCP server to get its credentials: a typed token, a reference to a `.env` variable, a token printed by a command, and an OAuth sign-in. It was parked before anything was approved, with the research findings saved, including that GitHub's hosted server needs a registered app for OAuth while most other hosted servers do not. |
