# No resume between sessions

Status: built
Date: 2026-11-18

The whiteboard no longer reloads an earlier session. Every launch is a fresh board, and the only things that persist are the visuals the user saved. A saved visual comes back only when the user points the skill at it. This reverses the resume behaviour in the first request (its assumption 13 and the `board.json` file).

## Decisions

- **Fresh board every launch.** No cards, no chat, usage at zero. The board, chat and usage live in memory, so a page reload during a running session still shows them.
- **Only saved visuals persist**: `<out>/<id>.json` per saved card and `result.json` (`{library, done, saved}`). `board.json` is no longer written or read.
- **A new, empty output folder per launch.** A folder that already holds JSON files is refused (exit code 2) and left untouched, so earlier saved visuals are never loaded or overwritten.
- **Continuing from a saved visual is explicit.** The skill passes the saved recipe file as `--existing`; it opens as the current visual (G1, round 0). A saved chart made for a different library than the session's is refused with a message naming the library to use; saved HTML tables are accepted in any session.
- **Unsaved work is lost when the session ends**, by Done or by the idle stop. The page says "Only saved cards are kept", asks once before finishing when cards exist and nothing is saved, and the closing message says how many visuals were kept.
- The expand or collapse choice for earlier rounds is kept for the browser tab only.

## Known limits

- Done asks "Nothing is saved. Finish anyway?" even when the only card is the unchanged current visual.
