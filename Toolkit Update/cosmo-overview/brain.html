The brain

Shared memory for the assistant and the team: short notes that outlive any one conversation.

The problem

The assistant forgets everything

An assistant starts every conversation knowing nothing about your work. So you explain the same facts again: what a column means, which table to trust, why a number is defined that way.

What one person works out stays with that person. A colleague who starts the same kind of work begins from zero.

What it is

A set of short pages, kept as ordinary files

The brain is a wiki: one page per topic, written as plain markdown files in a folder.

In plain terms

The brain: a shared folder of short note pages that the assistant can read before it answers, so it already knows what your team knows.

Where it lives

In a wiki folder of markdown pages. The files are not locked inside one tool.

What goes in

Facts that stay true: how data and systems behave, known traps, methods, metric definitions, agreed numbers.

Who can read it

It has two sides. Personal pages are your own. Team pages are shared. Lines reach the team side only when a person moves them there.

What the assistant reads

  1. Nothing yet. Run the request to fill this in.

Nothing read yet.

Running the request would light up the pages that bear on trend, with the lines between them, and dim the rest. The ones that light up are listed beside the graph. Larger circles are the pages most other pages link to.

The assistant reads the few pages that bear on the request, not the whole brain. That keeps the conversation short, and the answer matches what the team has already agreed.

How it works

From a passing fact to a page anyone can read

Four steps. The assistant does the writing; you decide when it files and what the team sees.

  1. Something worth keeping comes up

    During a session the assistant jots down each durable fact as one plain line. It asks itself two things: is this a result of the project (that goes to findings), and would someone starting other work want to know it first?

  2. Intake decides where it belongs

    When you ask it to, the filing step goes through the waiting facts without asking you questions. It works each one into the right personal page, or starts a new page from a template if the topic has none.

  3. It is written as a short page with its source

    Pages follow the wiki's own rules for layout, tags and sources. To share a page, you pick the lines and move them to the team page of the same name.

  4. Later sessions read the relevant pages

    At the start of new work, the assistant lists which pages and sections are worth reading, each with a reason, and reads only those. This works for you or a colleague.

The parts

The skills and helpers behind each step

A skill is a written guide the assistant follows. A subagent is a helper it starts for one focused job.

Skill

brain-file

Files the facts recorded so far into personal pages. Runs only when you ask, and asks no questions.

Skill

brain-ingest

Pulls the lasting facts out of documents you drop in a folder, then files them the same way.

Skill

brain-promote

Moves lines you pick from a personal page to the team page. The only step that changes team pages.

Skill

brain-cite

Lists the pages and sections worth reading for what you are doing, each with a reason, in a file called braincite.md.

Subagent

brain-filer

Decides where each fact belongs and writes it into the page. Creates a page when a topic has none.

Subagent

brain-extractor

Reads documents and returns the facts in them that will still be true next month.

Subagent

brain-promoter

Adds the lines you picked to the team page and removes them from your personal page.

Subagent

brain-context-analyst

Goes through the list of pages and picks the few worth reading for an ask.

The wiki app can also open the same folders, so you can browse the pages and review changes on screen.

What belongs

Facts go in the brain. Results and secrets do not.

In the brain

  • Facts that outlive a project, such as how a table behaves or a known gotcha.
  • Definitions and methods, including the organisation's standing definitions.
  • Decisions and the reason for them.
  • Reference numbers someone would look up again. Give the period and where it came from.
  • Something you are unsure of. Say in the fact that it is unconfirmed.

Not in the brain

  • A project's results. They go in that project's findings, tied to its plan.
  • Working choices for one project. Those belong in the plan.
  • Public or textbook knowledge, to-dos, one-off deadlines and scratch work.
  • Passwords, keys and other secrets.
  • Personal details about people.

Why bother

What you get

Less re-explaining

A fact is written down once. The next session reads it instead of asking you.

The same answer for everyone

Team pages hold one agreed version of a definition or a trap, so colleagues start from the same facts.

Knowledge that lasts

It sits in files, so it survives a closed conversation. It is not tied to one tool.

Cheaper sessions

The assistant reads a few short sections picked for the job, not a long briefing every time.

What to expect

The brain is only as good as what goes in. A page without a source is hard to trust, so keep the source with each fact. Pages go out of date, so prune them now and then. Nothing private goes in: no secrets, no personal details.
