Deliverables

Reports, decks and dashboards, built from parts that already work.

What counts as a deliverable?

Three things, each with its own skill (a short written guide the assistant follows). You ask in plain words and the assistant picks the right one.

A report

The analysis skill explores a question, then writes it up as a web page when you say so. It doesn't build a view you open every week.

A slide deck

The presentation skill turns work that already exists into slides. It doesn't do the analysis, and it doesn't make PowerPoint files.

A dashboard

The dashboard skill makes a standing view with filters on live data. It isn't for a one-off story.

Why do we use a script to make them?

Say you want a chart of cost by region. The script copies a ready-made chart from our shared design library (a folder of charts, tables and slides) into one small file. It fills that file from your data and prints the few lines to reword. Then it checks that nothing is cut off.

  • The same look every time.
  • When the numbers change, you refresh. You don't redo the deck.
  • Problems show up in a check, not in the meeting.
How it works, step by step

  1. Read the library's list

    A short index, not every file.

  2. Pick items

    One chart, table or slide per point.

  3. Copy each in

    Each becomes one small file in your piece.

  4. Point it at your data

    Name the columns that feed it.

  5. Edit the few lines you want changed

    A title, a colour, a third line.

  6. Build and look

    It builds, takes a picture and checks it.

  7. Save one you like back

    It goes into the library for everyone.

Isn't it faster to ask the AI to write the whole page?

Not really, because most of a page is the same every time: the styling and the chart-drawing code. In one sample five-chart report, the page was about 23 KB, and about 63% of it was that unchanging code. The assistant's own writing was under about 1,000 tokens (a token is a chunk of text you pay and wait for).

23KBone finished five-chart page
63%of it code that never changes
25KBa library chart file
4KBthe part that gets copied

All of this is from one sample, so read it as an example, not a promise.

How do I know what a chart needs before I add it?

You ask to see it first. A show step prints just that item's parts: which ones are required, which of your columns fit each, and a ready-made command to copy it in. Every item has its own parts, so the list is different for each one.

What if the chart is close but not quite right?

It still goes in. If a part can't be filled from your data, it goes in on placeholder data with a MANUAL line saying exactly which line to edit by hand. A tweak to the look is usually a few lines in one file. The library covers common visuals, not every one.

Two helpers (subagents, each started for one job) take care of the rest. One suggests which items fit what you're making, and says plainly what the library doesn't have. The other saves a chart you like back into the library.

What happens when the data changes?

You rebuild. The figures in a report's text are pulled from the data, so they update on their own. Charts refill and keep your edits. A theme (one set of colours and fonts) changes the whole look with one command.

  • New data means a rebuild, not a rewrite.
  • Your hand edits stay.
  • A library item looks the same in a report, a deck and a dashboard.
