Deliverables

Reports, decks and dashboards made from reusable parts, so each one starts from something that already works.

The idea

A skill that builds from parts

A deliverable skill helps your assistant make a finished piece of work: a report, a slide deck or a dashboard. It does not draw each chart from nothing. It copies a ready-made chart, table or slide from a shared folder and fills it with your data.

In plain terms

Skill: a short written guide the assistant follows for one kind of job.

In plain terms

Design library: a shared folder of ready-made charts, tables and slides, with a short list that describes each one.

In plain terms

Theme: one set of colours and fonts. Change it and the whole look changes.

Three skills

Pick the one that fits the job

Analysis

It explores a question in the conversation first, then writes it up as a report. Use it for questions such as "where is the cost rising, and why?". Ask in plain words, and say "write it up" when you want the report. You get a web page with one section per point: a chart or table, and a few short lines whose figures come from the data. It does not build a standing weekly view. That is a dashboard.

Presentation

It makes a slide deck from work that already exists, such as findings, a report or a dashboard. Use it when you need to tell people about results. Name the audience and the one message you want to land. You get a deck that opens in the browser, with one file per slide. It does not make PowerPoint files, and it does not do the analysis itself.

Dashboard

It makes a standing view with tabs and filters on live data. Use it when people come back to the same numbers each week or month. Say who uses it, which questions it answers and which filters it needs. You get a small app that reads your data files and redraws when a filter changes. It does not tell a one-off story. For that, use a report or a deck.

How they all work

The same seven steps, every time

All three skills share one way of working. That is why a chart looks and behaves the same in each.

  1. Read the library's list

    The assistant reads a short index of what the library holds, not every file.

  2. Pick items

    It chooses one chart, table or slide for each point you want to make, and can use a show command to look at an item and the data it needs first.

  3. Copy each into your piece

    Each pick is copied into your report, deck or dashboard as one small file. If a part is missing, the file carries a MANUAL note saying what to fill in.

  4. Point it at your data

    It names which columns feed each item. The figures are filled in from the data.

  5. Edit the few lines you want changed

    A title, a colour, a third line on a chart. Your edits stay when the data refreshes.

  6. Build and look

    It builds the piece, takes a picture and checks it, so a problem is caught before you see it.

  7. Save a version you like back to the library

    A visual worth reusing goes back into the library for everyone.

Helper: the graphic designer

A subagent (a helper started for one job) that suggests which library items suit what you are making. It says plainly what the library does not have.

Helper: the design librarian

A subagent that saves visuals you like back into the library and checks that each saved item works. It leaves your original untouched.

Efficiency

Why this is more efficient

Most of a report is the same in every report. The assistant should not write it again each time.

Without the library

Everything written fresh

  • The assistant writes the page styling and the chart code each time
  • More to write, more to wait for, more to check
  • Each report looks a little different

With the library

Copy, fill, edit

  • The shared code is copied in, not written
  • The assistant writes only the words and the few lines that differ
  • Every report shares one look

Token: a chunk of text the assistant reads or writes. You pay and wait per token.

These figures come from one sample report, so read them as an example, not a promise. A small change to an added chart is a few lines in one file.

Reproducible

Why this is reproducible

New data, a rebuild

The numbers in a report's text are pulled from the data. When the data changes, you rebuild. You do not rewrite.

Charts refill

Charts take in the new figures and keep the edits you made by hand.

One command for a theme

A theme changes the whole look at once, in one command.

The same everywhere

A library item looks the same in a report, a deck and a dashboard.

What to expect

An added chart usually needs a few edits before it fits your data. Sample captions come with the copied item, and you must reword them. The library covers common visuals, not every one. When something is missing, the graphic designer helper says so, and you can build your own and save it back.
