# Analysis folders

Folders made by the `analysis` skill (`run.py`, `config.py`, `sections/`). No planning interview, no hand-written plan or shell.

## How it maps

| Commentary concept | In an analysis folder |
| --- | --- |
| Plan | The folder's `README.md` (request and storyline) |
| Shell | Generated by `run.py` at `commentary/commentary_shell.json`. Never edit it |
| Unit question (`covers`) | Each section file's `QUESTION` |
| Unit tables | Each section's `summary` tables in `data/sections/` |
| Unit `notes` | Each section file's `NOTES`, including any filter or adjustment made in `compute()` |
| Shell `question` | `config.py` `QUESTION` |
| Audience | `config.py` `AUDIENCE` |
| Units | Per section: a heading (one sentence) and a body (up to three bullets). Plus the answer: written last from the sections' commentary, shown at the top |
| Unit ids | `C1`, `C2` ..., given by `run.py`, never change. `python run.py status` lists them |
| Output | `commentary/commentary.json`. In the report, each block has a collapsed line with its id and source |

## Run

| Task | Command (from the analysis folder) |
| --- | --- |
| Write what is missing or out of date, rebuild the report | `python run.py commentary` |
| See the state of each unit | `python run.py status` |
| Hand edit | `python <this skill>/scripts/edit.py commentary/commentary_shell.json <unit> --bullet "..."`, then `python run.py build` |
| Rewrite a unit on purpose | Change that section's `QUESTION` or `NOTES`, then `python run.py commentary` |

Never call `generate.py` or `fill.py` directly on an analysis folder. `run.py` tracks which data each piece was written for and hides commentary that no longer matches.

## After every run

- As `running.md`: read `commentary/commentary_run.md`, report the counts, show every unverified bullet and every "missing" note.
- The fix is almost always in the section file: add the figure or comparison to its `summary` table, or correct `NOTES`.
